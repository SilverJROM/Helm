  The half that isn't the UI

  The log genuinely can't answer your question today. build_audit_record() (diwa/recall.py:443)
  writes five fields: task, filters, ids, scores, empty. It gains four:

  ┌─────────┬──────────────────────────────────────────────────────────────────────────────────┐
  │  Field  │                                       Why                                        │
  ├─────────┼──────────────────────────────────────────────────────────────────────────────────┤
  │ ts      │ UTC timestamp — every line today is undated                                      │
  ├─────────┼──────────────────────────────────────────────────────────────────────────────────┤
  │ caller  │ who asked; self-reported by the client, MCP stdio carries no verifiable identity │
  ├─────────┼──────────────────────────────────────────────────────────────────────────────────┤
  │ surface │ cli or mcp — they share run_recall by design and are indistinguishable today     │
  ├─────────┼──────────────────────────────────────────────────────────────────────────────────┤
  │ payload │ the exact framed bytes that agent received — "what was sent to them"             │
  └─────────┴──────────────────────────────────────────────────────────────────────────────────┘

  run_recall gains two optional params (caller, surface), defaulted so every existing call site
  keeps working. The framed output itself is untouched — D-UI-6 holds, and recall's byte-level
  tests must pass unchanged.

  Two consequences I'd rather say now than discover later:
  - Log growth. Storing payloads takes lines from ~200 bytes to a few KB. 5.7 KB today → maybe 1–2
  MB after a few thousand recalls. Documented size note plus a manual truncation story, no
  rotation daemon.
  - ts is wall-clock, which the project bans in ranked output. It's in the audit line, not the
  ranked path, so the determinism contract is intact — but planning verifies no existing test
  asserts audit-record equality.

  The web layer

  Six routes, all GET. Any other method → 405 by construction, not by check:

  GET /                      the page
  GET /api/records           list — filter project, kind, free-text; stable sort
  GET /api/records/<id>      one record whole
  GET /api/audit             rows newest-first, payload inline
  GET /static/app.html       the one asset
  *                          404

  Records come from the index opened mode=ro (D-UI-5) — the record table already carries
  everything both views need, so no second parser and no corpus walking. Audit rows are parsed
  line-by-line from eval/runs/recall.jsonl with .get() throughout, so pre-cycle lines render as
  "unattributable" rather than crashing.

  One design call worth your eye: browse search is plain substring matching over title/tags/body —
  not recall's ranking. Recall applies the coverage floor, which is correct for agents and wrong
  for browsing: it would hide records from you while you're trying to see what exists. Browse
  shows everything that matches; recall stays the discriminating path. I'll record that as D-UI-7.

  client-side), no pagination (76 records fit one page), no sort controls beyond the stable
  default, no CSS beyond what makes it readable. The audit fields were not cut — that's where the
  actual value is.
