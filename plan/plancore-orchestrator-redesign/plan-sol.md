## Protocol decisions used by the slices

The non-adaptive protocol consumes exactly two resolved `coPlannerSeats`. A roster of any other size
typed-BLOCKs rather than truncating or inventing seats; the existing staffing resolver and its
`plancore` label remain unchanged. Round 1 gives A and B separate private workspaces. Round 2's proposer
is the lower full SHA-256 draft, with seat id as the deterministic tie-break for identical drafts; the
other seat signs. Every later round swaps proposer and signer. Even byte-identical round-1 drafts go
through a signer turn, because promotion is permitted only after an R3.11 signature.

The signature callback reuses B5's parseable form:
`VERDICT-READY — CLEAN SIGNED plan=<sha12>`. Rejection is
`VERDICT-READY — BROKEN plan=<sha12> objections=<N>; 1. ...`; malformed numbering, more than 20
objections, or a non-decreasing count typed-BLOCKs. The signer never receives either independent draft.

A committed draft or candidate is an immutable directory bundle containing requirements and plan.
Publication uses a same-directory staging rename; canonical promotion stages both canonical files,
renames each, then atomically publishes a hash-pair commit marker. Engine readers require the marker,
so a crash between file renames cannot expose a mixed pair to ingest. The marker binds both hashes,
while the signer retains B5's required `plan=<sha12>` binding to the candidate plan bytes.

Round-1 filesystem privacy is mandatory, not prompt etiquette. Planning-seat spawns use the existing
Landlock strict-read profile with only the project/context inputs and that seat's private workspace
readable. A configuration whose project/read allowlist overlaps a sibling workspace fails before
spawn; it never silently falls back to read-all. The service capability layer independently rejects
cross-seat read and list operations.
